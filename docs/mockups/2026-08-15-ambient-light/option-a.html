Ambient Light — Option A · Instrument strip

Both surfaces are read under time pressure in a dim room, so this option spends nothing on spectacle and everything on density: each control is one row on a rack — label left, instrument right, hairline between. The only picture anywhere is the one control that genuinely needs to be a picture, the day track, whose fill is the interpolated palette, so the same 12px strip serves as scrubber, keyframe map and gradient proof. No hero visualisation, no preview thumbnails, no chrome that competes with the canvas (PRODUCT #1 — the map is the stage).

Instrument vocabulary

Five shapes, defined once, reused on both surfaces. Every state below is carried by shape and word, never by colour alone — the Table's accent is literal white, so colour could not carry it even if we wanted it to.

Day track. The fill is the live interpolated palette, so the control shows the gradient it edits. Same strip in both apps.
Keyframe tick. One hairline per authored key (dawn / morning / noon / evening / night). Ticks are on the track, never separate chips.
LOCAL Local badge + dashed well. Anything inside a dashed enclosure is preview-only and never leaves this browser. Used once: the Editor day-scrub.
OVERRIDE Inverted chip. Reserved for DM-forced state. Inversion + lock glyph + the word — three encodings, zero hue.
N/A Not-applicable tag + dimmed row. Dim alone reads as a bug; the tag plus a one-line reason reads as a rule. Never omission.
● ◐ ○ Moon glyphs. Filled / half / hollow, each with its word underneath. Glyph is decoration for the word, not a replacement.

03

Engineering notes

  • One new primitive, both apps. The day track is a single component parameterised by token set: a <input type=range> with opacity 0 over a gradient div plus absolutely-positioned tick hairlines. Editor instance uses SliderInput's start-ref / commit-on-release idiom; the Table instance rides the set-environment optimistic-echo pattern with its 4s pending fallback.
  • The gradient is the interpolation. Track fill is linear-gradient(90deg in oklab, …keyframes), which is the same OKLCH-family interpolation the renderer does — the control cannot drift from the grade it edits, and there is no second source of truth.
  • Compass is the only genuinely new widget. ~60 lines: a rotary with pointer drag, arrow-key stepping (1° / 15° with Shift), and a numeric readout that is also the text input. Everything else is Segmented, Switch, ToggleSwitch, ColorField, SelectInput and the existing 24px preset row, unchanged.
  • Lift before the second copy. This is the second consumer of Segmented/Switch — move them out of FogTool.tsx into session/client/src/components/ui/ rather than a third private copy. Canvas needs its own Moss-token Segmented; it has none today.
  • Badge is one pure function. (environment, clock, sky, override) → {level, provenance, qualifier} — the same coupling resolver the server uses for vision gating, rendered as two lines. No colour branch in it at all.
  • Not-applicable, not absent. Disabled rows keep their DOM and their labels, add aria-disabled plus the N/A tag, and the reason renders once per section, not once per row.
  • Cost of the plates. The map imagery here is CSS only — no dressed Fieldstone Keep capture exists in docs/. Before adjudication, re-shoot these six states from the live dev server so the grade is judged on real art rather than gradients.
